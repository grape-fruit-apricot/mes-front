# Hansol MES Front

기존 Spring Boot / Oracle 백엔드에 연결하는 React + Vite 프로젝트입니다.

## 실행

Node.js 20.19+ 또는 22.12+가 필요합니다.

```powershell
cd front/mes
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 열어 주세요. 백엔드는 별도로 실행되어 있어야 하며, 기본 API 프록시 주소는 `http://localhost:8080`입니다. 다른 주소를 사용하려면 `.env.example`을 `.env.local`로 복사하고 `API_PROXY_TARGET`을 설정한 뒤 Vite를 다시 실행합니다.

```powershell
npm test
npm run build
npm run preview
```

`preview`는 빌드 결과 확인용이며 동일한 API 프록시를 사용합니다. 운영 배포는 `dist`를 정적 제공하고 `/api`를 백엔드로 전달하는 리버스 프록시를 별도로 설정해야 합니다. DB 비밀번호는 프론트엔드에 넣지 않습니다.

## 화면과 동작

- 작업지시: 목록/상세, 생성, 작업 시작, 생산실적 등록, 양품 전량 입고
- 생산실적: 목록/상세, 입고, 관련 작업지시 보기
- 입고이력: 목록/상세, 관련 작업지시 보기
- 재고현황 및 품목정보: 목록/상세
- 품목 코드·이름 검색, 작업 상태와 기간 검색, 10건 단위 페이지 이동

전체 건수 API가 없으므로 통계 카드는 **현재 페이지 기준**입니다. 다음 페이지를 조회하여 다음 버튼 활성 여부를 결정합니다. 기간은 작업지시 생성일 / 실적 등록일 / 입고일에 각각 적용합니다. 품목과 재고에는 상태 및 기간 검색을 적용하지 않습니다. 작업지시 생성의 품목 선택은 모든 품목 페이지를 순회하여 제공합니다.

수량은 정수이며 양품+불량=지시 수량, 불량 발생 시 사유 필수 규칙을 검증합니다. 전량 불량은 실적 등록은 가능하지만 입고할 수 없습니다. 상세 화면에서 동작 전에 최신 상태를 조회하고, 서버 오류 메시지를 표시합니다. 테스트 데이터나 가짜 성공 응답은 사용하지 않습니다.

## 수동 연동 확인

1. 백엔드와 Oracle을 실행하고 품목정보를 조회합니다.
2. 고유한 작업지시 번호, 품목, 지시 수량 10으로 작업지시를 생성합니다.
3. 상세에서 작업을 시작하고 양품 9 / 불량 1 / 불량 사유로 실적을 등록합니다.
4. 양품 전량 입고 후 입고이력 및 해당 품목 재고가 9 증가했는지 확인합니다.
5. 입고 완료 건에는 재입고 버튼이 표시되지 않는지 확인합니다.

위 수동 확인은 실제 DB에 작업지시·실적·입고를 등록합니다. 자동 단위 테스트는 DB를 변경하지 않고 수량 검증 및 입고 가능 조건을 검사합니다.
